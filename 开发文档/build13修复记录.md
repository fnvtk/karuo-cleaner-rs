# build 13 修复记录

## 用户遇到的问题

大批量整理期间，应用的全局“忙碌”开关把只读操作也拦住，导致读取应用、读取登录项和浏览结果继续弹出“正在处理文件”。大批次同时会对每个文件重写整份清理历史，文件数量增加时速度明显变慢。

## 修改

- 文件整理期间放行只读页面、应用列表、登录项读取、空间目录浏览和 AI 分析；新的文件扫描、移动、恢复、永久清理和启动项修改仍等待当前工作完成。
- 为文件操作增加异常退出时的忙碌状态复位，避免后台线程异常后一直锁住界面。
- 整批清理前一次性写入恢复意图，处理后一次性更新历史；保持每个文件移动前的身份重验、系统废纸篓和恢复机制。
- 历史锁繁忙时读取最近一次原子保存的记录快照，避免把“暂时读不到”显示成“没有历史”。
- 空间透镜继续使用50项显示分页；分页不截断已经建立的目录索引，5,101项目录测试确认所有项目都能逐页访问。

## 验证

- `cargo test --offline --quiet`：48项通过。
- release 安装包自建文件夹具：16项通过，包含移入废纸篓、恢复、越界拒绝、文件变化拒绝和应用包边界。
- 新增8个自建文件的批量移动与恢复测试通过。
- 当前电脑旧版进程在 build 13 构建期间仍处理用户已启动的大批操作；观察到历史29,352条记录和5条待处理恢复意图。未强制退出或打断该进程。
- build 13 待在旧进程安全结束后替换正式安装包，并完成GUI回读。
